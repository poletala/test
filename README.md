# Frontend Interview Trainer

Интерактивная платформа для подготовки к техническим собеседованиям на позицию
**Middle Frontend Developer**. Приложение помогает не заучивать варианты ответов, а
разбирать механизмы JavaScript, React, TypeScript, MobX, браузера и архитектуры.

Интерфейс, вопросы, варианты, объяснения, подсказки и учебные материалы написаны
по-русски. Техническая часть и код — на английском.

> Проект работает полностью в браузере: без backend, авторизации и платных API.
> Прогресс хранится в `localStorage`.

## Возможности

### Шесть режимов обучения

1. **Режим обучения** — мгновенная проверка и подробный разбор после каждого ответа.
2. **Режим интервью** — таймер на вопрос, без подсказок и разбора до финала.
3. **Работа над ошибками** — только вопросы, где были ошибки.
4. **Случайная практика** — смешанная выборка из всех модулей.
5. **Middle Challenge** — только Junior+ и Middle.
6. **Закладки** — сохранённые вопросы для повторения.

Перед стартом можно выбрать модуль, количество вопросов, уровни сложности и время
на вопрос в режиме интервью.

### Шесть форматов вопросов

- одиночный выбор;
- множественный выбор;
- предсказание вывода кода;
- поиск бага;
- сценарий из инженерной практики;
- дополнение кода с безопасной проверкой введённой строки.

Пользовательский код **не выполняется**. Для `code-completion` ответ сравнивается
с нормализованными допустимыми вариантами.

### Объяснения

У каждого вопроса есть:

- подробное объяснение механизма;
- объяснение каждого варианта ответа;
- типичные заблуждения;
- практический пример кода;
- совет, как отвечать на собеседовании;
- подсказка;
- короткое резюме для повторения;
- теги и тема.

При ошибке показываются правильный ответ, причина ошибки выбранного варианта,
пошаговый разбор и возможность сохранить вопрос в закладки. При верном ответе разбор
также доступен.

### Прогресс и аналитика

- пройденные вопросы и количество попыток;
- точность всех попыток и **точность первой попытки отдельно**;
- точность по модулям и темам;
- сильные и слабые темы;
- история последних ответов;
- закладки;
- результаты сессий;
- незавершённая сессия с возможностью продолжить;
- оценка готовности к Middle;
- полный сброс прогресса с подтверждением.

Прогресс сохраняется в `localStorage` после каждого ответа и переживает перезагрузку.
Вопрос не считается освоенным только потому, что пользователь в итоге выбрал верный
вариант: первая попытка хранится отдельно.

### Интерфейс

- тёмная тема по умолчанию и светлая тема;
- адаптивная вёрстка для desktop, tablet и mobile;
- подсветка синтаксиса без выполнения кода;
- клавиатурная навигация и видимые focus-состояния;
- семантические заголовки, `aria`-атрибуты, skip-link;
- модальные подтверждения;
- уведомления о действиях;
- поддержка `prefers-reduced-motion`.

## Быстрый старт

Требования: **Node.js 20+** и npm.

```bash
npm install
npm run dev
```

Vite покажет локальный адрес, обычно `http://localhost:5173/`.

### Основные команды

| Команда | Что делает |
|---|---|
| `npm run dev` | запускает dev-сервер |
| `npm run build` | проверяет TypeScript и собирает production-бандл |
| `npm run preview` | локальный просмотр production-сборки |
| `npm test` | запускает все тесты один раз |
| `npm run test:watch` | запускает тесты в watch-режиме |
| `npm run typecheck` | только проверка TypeScript |
| `npm run lint` | ESLint |
| `npm run validate:questions` | проверка целостности банка вопросов |
| `npm run deploy` | сборка и публикация `dist` на GitHub Pages |

> Скрипты `dev`, `build`, `preview`, `test` и `typecheck` запускаются через
> `scripts/run-with-temp.mjs`. Он перенаправляет `TEMP`/`TMP`/`TMPDIR` в локальную
> папку `.tmp`, чтобы Windows не блокировал удаление временного исполняемого файла
> esbuild. Это исправляет ошибку `Access is denied` при `npm run build` и не требует
> ручной настройки переменных окружения.
>
> Если вы запускаете команды из внешней песочницы, которая запрещает создание
> дочерних процессов, Vite/Vitest всё равно нужно запускать вне неё. Это ограничение
> конкретной песочницы, а не проекта.

### Поток состояния

```text
UI (observer)
   │ action
   ▼
RootStore
   ├── ProgressStore ──► LocalStorage
   ├── QuizStore ──────► активная сессия / результаты
   └── UiStore ────────► тема / уведомления
   │ observable
   ▼
observer-компоненты перерисовываются
```

Банк вопросов не импортируется в UI-компоненты напрямую: единственная точка
доступа — `src/data/index.ts` и `RootStore`.

## Как добавить вопрос

1. Откройте файл нужного модуля, например `src/data/react/part3.ts`.
2. Добавьте объект типа `Question` с уникальным `id`.
3. Выберите тему **строго из** `src/data/categories.ts`.
4. Для choice-вопроса добавьте ровно четыре варианта и объяснение каждому.
5. Укажите `correctAnswers` — массив id правильных вариантов.
6. Для `code-completion` заполните `completion.acceptedAnswers`, а `options` не добавляйте.
7. Для `code-output` и `find-bug` добавьте `code` и `codeLanguage`.
8. Запустите:

```bash
npm test
npm run typecheck
npm run validate:questions
```

Пример структуры:

```ts
{
  id: 'react-066',
  category: 'react',
  topic: 'useEffect и зависимости',
  difficulty: 'middle',
  type: 'code-output',
  question: 'Что выведет код?',
  code: '...',
  codeLanguage: 'jsx',
  options: [
    { id: 'a', text: '...', explanation: '...' },
    { id: 'b', text: '...', explanation: '...' },
    { id: 'c', text: '...', explanation: '...' },
    { id: 'd', text: '...', explanation: '...' },
  ],
  correctAnswers: ['a'],
  explanation: '...',
  commonMistakes: ['...', '...'],
  codeExample: '...',
  interviewTip: '...',
  hint: '...',
  summary: '...',
  tags: ['react', 'hooks'],
}
```

Не изменяйте UI под один вопрос и не добавляйте вопросы внутрь React-компонентов.

### Валидация банка

`src/data/validate.ts` проверяет:

- уникальность `id`;
- допустимую категорию, сложность и тип;
- принадлежность темы модулю;
- ровно четыре варианта у choice-вопросов;
- существование всех `correctAnswers`;
- непустые объяснения;
- наличие `code` для задач на код;
- корректную структуру `completion`;
- ожидаемое количество вопросов в каждом модуле;
- отсутствие дублирующихся формулировок.

## Хранение прогресса

Ключ LocalStorage:

```text
frontend-interview-trainer:progress:v1
```

Состояние содержит:

- `questions` — попытки, первая попытка, история, последний результат;
- `bookmarks` — id сохранённых вопросов;
- `sessions` — до 50 последних результатов;
- `activeQuiz` — снимок незавершённой сессии;
- `lastActivityAt`.

Особенности:

- запись происходит после каждого ответа, смены закладки и старта сессии;
- повреждённый JSON безопасно превращается в пустое состояние;
- квота браузера не должна ломать приложение;
- сброс прогресса доступен на главной странице и требует подтверждения;
- данные не отправляются на сервер.

Тема оформления хранится отдельно в ключе
`frontend-interview-trainer:theme`.

## Как считается готовность

Оценка готовности — прозрачная эвристика, а не AI-рейтинг и не гарантия оффера.
Для каждого отвеченного вопроса:

- **55%** — верный первый ответ;
- **20%** — верный последний ответ;
- **25%** — стабильность (доля верных среди всех попыток).

Неотвеченные вопросы дают 0 и снижают итог. Оценка считается по девяти направлениям:
основы JS, асинхронность, React, TypeScript, MobX, браузер, архитектура, тестирование
и практическая отладка. Итог — среднее по направлениям.

Пороговые зоны:

- `< 50` — слабый уровень;
- `50–69` — формируется;
- `70–84` — уверенно;
- `85+` — сильно.

## Деплой на GitHub Pages

Проект использует `HashRouter` и относительный `base: './'`, поэтому его можно
публиковать в подпапке репозитория без серверного rewrite.

### Вариант 1: `gh-pages`

```bash
npm run build
npm run deploy
```

Скрипт `deploy` публикует содержимое `dist` в ветку `gh-pages`.
В настройках репозитория выберите эту ветку как источник GitHub Pages.

### Вариант 2: GitHub Actions

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm test
      - run: npm run build
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
      - id: deployment
        uses: actions/deploy-pages@v4
```

Если сайт публикуется из корня пользовательского домена, относительный `base`
продолжит работать. Для нестандартной схемы URLs измените `base` в `vite.config.ts`.

- React 18.3.
